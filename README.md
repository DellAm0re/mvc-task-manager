# MVC: менеджер завдань на Python

Навчальний проєкт для дисципліни **«Архітектура та проєктування програмного забезпечення»**.

## Мета

Реалізувати архітектурний шаблон **MVC (Model–View–Controller)** на прикладі консольного застосунку для керування завданнями.

## Функціональність

- додавання завдань;
- перегляд списку завдань;
- позначення завдань виконаними;
- видалення завдань;
- обробка некоректного вводу.

Дані зберігаються **в оперативній пам'яті**, тому після перезапуску програми список очищається. Це свідоме спрощення навчального прикладу.

## Як працює MVC

- **Model** (`mvc/model.py`) — класи `Task` і `TaskRepository`: зберігання даних та бізнес-правила, зокрема перевірка назви.
- **View** (`mvc/view.py`) — клас `ConsoleView`: меню, введення даних і відображення результатів; не змінює модель.
- **Controller** (`mvc/controller.py`) — клас `TaskController`: приймає вибір користувача, викликає методи моделі й передає результат представленню.
- **Точка входу** (`main.py`) — створює компоненти та зв'язує їх між собою.

Потік керування:

```text
Користувач → View (вибір пункту меню)
                     ↓
               Controller
                 ↓     ↓
              Model   View → Користувач
```

У цій версії MVC контролер отримує введення через View. Model не знає про View або Controller, а View отримує для відображення лише дані `Task`.

## Запуск

Потрібен **Python 3.10 або новіший**, додаткові бібліотеки не потрібні. Відкрийте термінал **у корені репозиторію**:

```bash
python main.py
```

На Windows також можна виконати `py main.py`.

## Тестування

Із кореня репозиторію:

```bash
python -m unittest discover -s tests -v
```

Тести перевіряють створення й видалення завдань, валідацію, зміну стану, взаємодію контролера з моделлю та обробку помилок. Використовується стандартна бібліотека `unittest`.

## Висновок

MVC розділяє зберігання даних і бізнес-логіку, інтерфейс користувача та обробку дій. Завдяки цьому кожен компонент можна змінювати й тестувати окремо.
